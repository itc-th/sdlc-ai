# รายการตรวจ spec และ PR

ร่างเริ่มต้น เจ้าของ policy ต้องทบทวนและปรับก่อนใช้จริง

## ตรวจ spec
- [ ] ระบุระบบย่อยเป้าหมายและที่ได้รับผลกระทบครบ
- [ ] เกณฑ์ว่าเสร็จตรวจสอบได้ทีละข้อ
- [ ] แยกข้อเท็จจริงจากโค้ดออกจากข้อเสนอการออกแบบ
- [ ] ระบุข้อมูลส่วนบุคคลที่เกี่ยวข้อง และเก็บเท่าที่จำเป็น
- [ ] ระบุผลต่อสิทธิ์ผู้ใช้
- [ ] การเปลี่ยนโครงสร้างฐานข้อมูลมีแผนย้อนกลับ

## ตรวจ PR
- [ ] อ้างเลข issue และ spec ที่อนุมัติแล้ว
- [ ] ไม่มี secret, token หรือข้อมูลส่วนบุคคลในโค้ด เอกสาร และ log
- [ ] ตรวจสิทธิ์ที่ฝั่ง server ทุก API ที่เพิ่มหรือแก้
- [ ] ตรวจและจำกัดข้อมูลนำเข้าทุกจุด
- [ ] มีเคสทดสอบของสิ่งที่เปลี่ยน และชุดทดสอบผ่าน
- [ ] การกระทำสำคัญถูกบันทึกใน audit log
- [ ] ไม่เพิ่ม dependency ใหม่โดยไม่มีเหตุผลใน PR
- [ ] อัปเดต `docs/repo-map.md` ถ้าโครงสร้างเปลี่ยน
- [ ] ผู้อนุมัติไม่ใช่ผู้เขียน และไม่ใช่ agent
