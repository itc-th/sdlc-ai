# ร่าง intent จาก GitHub issue

รับเลข issue เป็น argument เช่น `/intent 123` ถ้าไม่ได้ให้เลขมา ให้ถามก่อน

## ขั้นตอน

1. อ่าน issue ด้วย `gh issue view <เลข> --comments --json number,title,body,labels,author,comments,url`
2. อ่าน `docs/intents/TEMPLATE.md` และดูโค้ดส่วนที่เกี่ยวข้องพอให้ระบุได้ว่าแตะระบบ โฟลเดอร์ ตาราง หรือ API ใด ห้ามแก้โค้ดในขั้นนี้
3. เทียบข้อมูลใน issue กับหัวข้อใน template แล้วถามผู้ใช้เฉพาะสิ่งที่ยังขาดและเดาไม่ได้ ถามรวมครั้งเดียว ไม่เกิน 5 ข้อ ลำดับความสำคัญ: ทำไมต้องทำ, เกณฑ์ว่าเสร็จ, ขอบเขตที่ไม่ทำ, ความเสี่ยง
4. เขียนไฟล์ `docs/intents/<ปี>-<เลข issue>-<ชื่อสั้นภาษาอังกฤษ>/intent.md` ตาม template
   - เขียนภาษาไทย กระชับ
   - เกณฑ์ว่าเสร็จต้องตรวจสอบได้ทีละข้อ
   - สิ่งที่ไม่มีข้อมูลให้ใส่ไว้ใต้ "คำถามที่ยังไม่มีคำตอบ" ห้ามแต่งขึ้นเอง
   - สถานะตั้งเป็น "ร่าง" เสมอ การอนุมัติเป็นหน้าที่ของคน
5. ประเมินระดับความเสี่ยง
   - สูง: แตะข้อมูลส่วนบุคคล สิทธิ์ผู้ใช้ หรือโครงสร้างฐานข้อมูล
   - กลาง: แตะข้อมูลงบประมาณ หรือ API ที่ระบบอื่นเรียกใช้
   - ต่ำ: อื่น ๆ
6. สรุปให้ผู้ใช้: path ของไฟล์ ระดับความเสี่ยง ใครต้องอนุมัติ และคำถามที่ยังค้าง
7. ถ้าผู้ใช้สั่ง ให้คอมเมนต์ลิงก์ไฟล์ intent กลับไปที่ issue ด้วย `gh issue comment` และเปลี่ยน label จาก `status:triage` เป็น `status:intent-draft`

## ข้อห้าม

- ห้ามเริ่มเขียนโค้ดหรือแผนการ implement ใน skill นี้
- ห้ามคัดลอกรหัสผ่าน token หรือข้อมูลส่วนบุคคลจาก issue ลงไฟล์ intent
- ห้าม commit หรือ push เอง เว้นแต่ผู้ใช้สั่ง
